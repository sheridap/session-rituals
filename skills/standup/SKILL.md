# /standup — Start-of-session context bootstrap

Re-establishes the best current working context at the start of a session (or after a multi-hour break), and surfaces the highest-impact next action. The **read-side mirror of `/handoff`**: where `/handoff` writes the durable artifacts at session-end, `/standup` reads them back and **regenerates** the briefing from live state — so it's always current, never a stale pasted block.

This exists because the most useful "start here" context does **not** auto-surface. At session start Claude only auto-loads `CLAUDE.md` + the memory index. The journal (the residue `/handoff` writes), the live ticket status, and the git/divergence state all have to be pulled deliberately. This skill pulls them, reconciles them, and synthesizes.

> **Operator-protocol note:** this orients; it does not gate. End with a recommended next action and hand control back — never stall waiting for permission to start.

## Parameters

Every environment-specific value this skill uses, with its default. **Do not edit this file to change them.** Override per repo in that repo's `CLAUDE.md` under a `## Session rituals` heading, one `- key: value` line each. A key that is absent takes the default.

| key | default | what it changes |
|---|---|---|
| `journal_dir` | `journal/` relative to the repo root | Where step 1 looks for dated entries (`YYYY-MM-DD.md`). May be an absolute path to a shared journal used by several repos. If the directory does not exist, step 1 reports "no journal" and the briefing leans on tickets + git. |
| `journal_repos` | none | Other repos whose own journal may hold a lane's arc (a stub in the shared journal may point there). Comma-separated paths. |
| `ticket_system` | `none` | `linear` (via the Linear MCP tools), `github` (via `gh issue list`), or `none`. Controls step 3. |
| `ticket_prefix` | none | Issue-id prefix (e.g. `ACME-`) used to recognise ticket references in commits and journal text. |
| `lock_check_cmd` | none | A command that reports whether another live session already owns a repo (`<cmd> <repo-path>`). When unset, step 4 skips the lock check. |
| `sync_sweep_cmd` | none | A **read-only** command that reports every local repo's currency (behind / diverged / dirty). When unset, step 4 covers only the in-scope repos with plain `git fetch`. |
| `sync_apply_cmd` | none | The mutating counterpart of the sweep (fast-forward only). Only ever *proposed* in step 5, never run by this skill. |
| `memory_dir` | `default` | `default` = Claude Code's auto-memory for the current project. Set a path only if your memory index lives elsewhere. |

**Never assumed:** no ssh to any host, no deploy command, no write to any external system. This skill is read-only except for the optional `sync_apply_cmd`, which it proposes and the operator runs.

## Procedure

Walk these in order. Steps 1–4 gather; step 5 synthesizes. Keep it tight — this is a briefing, not an audit.

### 0. Scope — what is this session about?
- `cwd` + the auto-loaded `CLAUDE.md` establish the repo (and product, if the repo belongs to one). State which repo(s) are in play. Read the `## Session rituals` block, if present, and note which parameters are set.
- If the intent is ambiguous (e.g., a bare `cwd` with no signal), ask the operator one question: what are they picking up? Don't guess across every repo on the machine.

### 1. Latest journal — the session residue
- Read the most recent entry in `journal_dir` (and the prior 1–2 if same-week / clearly related). Pull its **Next** / **Deferred** sections and any open threads — match them at **any heading depth** (`## Next` on a single-lane day, `### Next` when several lanes nest their arcs under `## <lane>` headers). This is the primary "where we left off" source and is NOT auto-loaded.
- **Follow the pointer stubs.** When `journal_repos` is set, a lane's arc — including its `Next` — may live only in that repo's own journal, with a two-line stub in the shared journal naming the repo. Read the current repo's own journal if it has one, and follow any stub for a lane whose work bears on today. A day that looks thin in the shared journal may just be recorded elsewhere.
- If the latest journal predates today by more than a day, note the gap (work may have happened unjournaled). If there is no journal at all, say so and move on.

### 2. Memory — the durable facts that matter here
- The memory index auto-loads; read the **bodies** of the memories relevant to the scoped work (project / working-state / feedback types). Honor any stale-guard ("verify before relying / if it names a file, confirm it still exists").

### 3. Tickets — live status truth
- `ticket_system: linear` — query the relevant team(s) for **in-progress + recently-updated** issues (e.g., `list_issues` with a short `updatedAt` window, or assignee=me).
- `ticket_system: github` — `gh issue list --state open --assignee @me` plus anything updated in the last few days.
- `ticket_system: none` — skip; git and the journal carry status.
- Note what's open, blocked, or was last touched. The ticket system is the status plane — trust it over the transcript.

### 4. Git + divergence — what's mid-flight, what drifted
First, if `sync_sweep_cmd` is set, run it. It is the **whole-machine currency picture**: a read-only sweep of every local repo reporting what is behind (fast-forwardable), diverged, dirty, detached, or missing. Carry any clean fast-forwards it lists into step 5. Without it, cover only the in-scope repos below.

Then, for each in-scope repo (start with `cwd`'s repo; add others the journal or tickets point at):
- If `lock_check_cmd` is set, run it against the repo before reading further: another live session may own it. Report, don't cross.
- `git fetch`, then report **ahead/behind** local vs the default branch on origin — surface divergence **before** branching (this is the discipline that prevents the unpushed-local-commits trap). Never `reset`/force here; just surface.
- `gh pr list` (open PRs + state), current branch, and any uncommitted work.
- Note **parallel-session activity**: commits landed on origin since the last journal entry — another session may have shipped relevant work (decisions, deploys, schema changes).

### 5. Synthesize — the standup briefing
Produce a tight briefing (not a recap of everything read):
- **Where things stand** — 1–3 lines of current state.
- **Top 1–3 next priorities** — reconciled from the journal `Next` + open tickets, in impact order.
- **Watch-outs** — divergence, stale/unverified claims, open gates, anything mid-flight.
- **Machine currency** — if the step-4 sweep showed clean fast-forwards and `sync_apply_cmd` is set, offer to bring the machine current now with that command. It *mutates* (advances refs), so propose it — don't auto-run.
- **Recommended first action** — the single highest-impact thing to start, phrased to begin immediately.

## Self-check — do not claim oriented until all pass
- [ ] Latest journal entry read (or "no journal" stated); its `Next` / `Deferred` surfaced
- [ ] Relevant memory bodies + tickets (in-progress/recent, or `none` stated) reviewed
- [ ] `git fetch` + ahead/behind + open PRs checked across the in-scope repo(s) — nothing mid-flight or diverged missed
- [ ] A synthesized briefing + a single recommended first action presented (not a raw dump)
- [ ] If `sync_sweep_cmd` is set: the sweep ran; clean fast-forwards surfaced as a proposed action

## Notes
- Pairs with `/handoff`: handoff writes a `Next` section → standup reads it. Match it at any depth — `## Next` on a single-lane day, `### Next` per lane when several lanes nest their arcs in one file. If a session ended without a journal entry, say so — the briefing will be weaker and should lean harder on tickets + git state.
- **Two bootstrap paths — don't conflate them.** `/standup` is the *heavy* cold-start bootstrap: a new day, a multi-hour break, or any time no fresh resume prompt is in hand. If you're resuming from a just-emitted `/lane-reset` prompt (an intra-day ticket boundary), that prompt **is** your bootstrap — paste it and keep working; do **not** run `/standup`. Running the heavy read at every ticket seam is exactly the all-day-session cost `/lane-reset` exists to avoid.
- Read-only by design for observation: the step-4 sweep is the read-only command, and the skill *proposes* fixes rather than making them. The one mutation it may offer is `sync_apply_cmd` (fast-forward only) — offered and operator-gated, never automatic. It still never `reset`s/force-pushes/commits — that's the operator's call once oriented.
- Could later be promoted to a `SessionStart` hook for auto-bootstrap; kept operator-invoked for v1 to avoid per-session cost/noise.
