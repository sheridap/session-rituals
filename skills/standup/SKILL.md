# /standup — Start-of-session context bootstrap

Re-establishes the best current working context at the start of a session (or after a multi-hour break), and surfaces the highest-impact next action. The **read-side mirror of `/handoff`**: where `/handoff` writes the durable artifacts at session-end, `/standup` reads them back and **regenerates** the briefing from live state — so it's always current, never a stale pasted block.

This exists because the most useful "start here" context does **not** auto-surface. At session start Claude auto-loads `CLAUDE.md` and, where auto-memory is on, the memory index. The journal (the residue `/handoff` writes), the live ticket status, and the git/divergence state all have to be pulled deliberately. This skill pulls them, reconciles them, and synthesizes.

> **Operator-protocol note:** this orients; it does not gate. End with a recommended next action and hand control back — never stall waiting for permission to start.

## Parameters

Every environment-specific value this skill uses, with its default. **Do not edit this file to change them.** Override in the `CLAUDE.md` at the root of the repo you are working in, under a `## Session rituals` heading, one `- key: value` line each. A key that is absent takes the default. If several `CLAUDE.md` files are loaded (user-level, repo root, a nested directory, `CLAUDE.local.md`), the one closest to `cwd` wins per key.

| key | default | what it changes |
|---|---|---|
| `journal_dir` | `journal/` relative to the repo root | Where step 1 looks for dated entries (`YYYY-MM-DD.md`). May be an absolute path to a journal shared by several repos. If the directory does not exist, step 1 reports "no journal" and the briefing leans on tickets + git. |
| `journal_repos` | none | Comma-separated paths (absolute, or relative to the repo root) of other local repos that keep their own `journal/`. A stub in the shared journal may point there. |
| `lane_name` | the repo's directory basename | The name `/handoff` used for this repo's section heading (`## <lane_name> lane`). |
| `ticket_system` | `none` | `linear` (via the Linear MCP tools, which must be connected), `github` (via `gh`), or `none`. Controls step 3. |
| `ticket_prefix` | none | Issue-id prefix (e.g. `ACME-`) used to recognise ticket references in commits and journal text. |
| `ticket_team` | derived from `ticket_prefix` without the dash | Linear team key to scope queries to. Without it a Linear query covers the whole workspace. |
| `lock_check_cmd` | none | `<cmd> <repo-path>` — exits 0 when no *other* live session holds that repo, non-zero when one does, printing the holders. The command must exclude the calling session itself. When unset, step 4 skips the lock check. |
| `sync_sweep_cmd` | none | A **read-only** command that reports every local repo's currency (behind / diverged / dirty). When unset, step 4 covers only the in-scope repos with plain `git fetch`. |
| `sync_apply_cmd` | none | The mutating counterpart of the sweep (fast-forward only). Only ever *proposed* in step 5, never run by this skill. |
| `memory_dir` | `default` | `default` = Claude Code's auto-memory directory for the current project. Set a path only if your memory index lives elsewhere. |

**Assumed tools:** `git`. `gh` is used only when it is installed and the repo's `origin` is on github.com; otherwise the PR check reports "not checked". Linear MCP tools are used only when `ticket_system: linear`.

**Never done:** no ssh, no deploy, no write to any external system, no git mutation. This skill is read-only except for the optional `sync_apply_cmd`, which it proposes and the operator runs.

## Conventions shared with `/handoff` and `/lane-reset`

- **Date.** `D` is the date the harness injected at session start, if it injects one; otherwise `date +%F` run once at first invocation this session and reused. Never re-derive `D` mid-ritual.
- **Journal layout.** `<journal_dir>/D.md`, one `## <lane_name> lane` h2 per repo that worked that day, h3 sections `Shipped` / `Decisions` / `Learnings` / `Deferred` / `Next` under it. A repo that journals in its own tree leaves a one-line stub in the shared journal: `## <lane_name> lane — journaled in <repo>/journal/D.md (<sha>)`.
- **Memory layout.** `<memory_dir>/MEMORY.md` is the index, one line per fact; each fact is its own file with frontmatter `name`, `description`, `type` (`feedback` / `reference` / `project`). If no index exists and `memory_dir` is `default`, memory steps are skipped and say so.
- **Resume prompt.** `/handoff` ends the day with one; the next morning the operator pastes it as the first message *and then runs `/standup`*, which reconciles it against live state. `/lane-reset` emits a smaller one at a ticket boundary, and after that paste `/standup` is *not* run.

## Procedure

Walk these in order. Steps 1–4 gather; step 5 synthesizes. Keep it tight — this is a briefing, not an audit.

### 0. Scope — what is this session about?
- `cwd` + the auto-loaded `CLAUDE.md` establish the repo. State which repo(s) are in play. Read the `## Session rituals` block, if present, and note which parameters are set.
- If a resume prompt was pasted just before this, treat it as the seed: verify its claims against the sources below rather than repeating them.
- If the intent is ambiguous (e.g., a bare `cwd` with no signal), ask the operator one question: what are they picking up? Don't guess across every repo on the machine.

### 1. Latest journal — the session residue
- Read the most recent entry in `journal_dir` (and the prior 1–2 if same-week / clearly related). Pull its **Next** / **Deferred** sections and any open threads — they sit under `### Next` inside each `## <lane> lane` section. This is the primary "where we left off" source and is NOT auto-loaded.
- **Follow the pointer stubs.** A `## <lane> lane — journaled in <repo>/...` line means that lane's arc — including its `Next` — lives in that repo's own journal. Read the current repo's own `journal/` if it has one, and follow any stub for a lane whose work bears on today. A day that looks thin in the shared journal may just be recorded elsewhere.
- If the latest journal predates `D` by more than a day, note the gap (work may have happened unjournaled). If there is no journal at all, say so and move on.

### 2. Memory — the durable facts that matter here
- If a memory index exists, read the **bodies** of the entries relevant to the scoped work (`project` and `feedback` types first). If an entry says to verify something before relying on it, verify. If there is no index, skip and say so.

### 3. Tickets — live status truth
- `linear` — query `ticket_team` for **in-progress + recently-updated** issues (a short `updatedAt` window, or assignee = me).
- `github` — `gh issue list --state open --assignee @me` plus anything updated in the last few days.
- `none` — skip; git and the journal carry status.
- Note what's open, blocked, or was last touched. The ticket system is the status plane — trust it over the transcript.

### 4. Git + divergence — what's mid-flight, what drifted
First, if `sync_sweep_cmd` is set, run it. It is the **whole-machine currency picture**: a read-only sweep of every local repo reporting what is behind (fast-forwardable), diverged, dirty, detached, or missing. Carry any clean fast-forwards it lists into step 5. Without it, cover only the in-scope repos below.

Then, for each in-scope repo (start with `cwd`'s repo; add others the journal or tickets point at):
- If `lock_check_cmd` is set, run it against the repo before reading further: another live session may own it. Report, don't cross.
- `git fetch`, then report **ahead/behind** local vs the default branch on origin — surface divergence **before** branching (this is the discipline that prevents the unpushed-local-commits trap). Never `reset`/force here; just surface.
- Open PRs: if `gh` is installed and `origin` is on github.com, `gh pr list`; otherwise report "PRs: not checked". Current branch, and any uncommitted work.
- Note **parallel-session activity**: commits landed on origin since the last journal entry — another session may have shipped relevant work (decisions, deploys, schema changes).

### 5. Synthesize — the standup briefing
Produce a tight briefing (not a recap of everything read):
- **Where things stand** — 1–3 lines of current state.
- **Top 1–3 next priorities** — reconciled from the journal `Next` + open tickets, in impact order.
- **Watch-outs** — divergence, stale/unverified claims, open gates, anything mid-flight.
- **Machine currency** — if the step-4 sweep showed clean fast-forwards and `sync_apply_cmd` is set, offer to bring the machine current now with that command. It *mutates* (advances refs), so propose it — don't auto-run.
- **Recommended first action** — the single highest-impact thing to start, phrased to begin immediately.

## Self-check — do not claim oriented until all pass
- [ ] Latest journal entry read (or "no journal" stated); its `Next` / `Deferred` surfaced
- [ ] Memory bodies read (or "no index" stated) + tickets reviewed (or `none` stated)
- [ ] `git fetch` + ahead/behind checked across the in-scope repo(s); PRs checked or "not checked" stated — nothing mid-flight or diverged missed
- [ ] A synthesized briefing + a single recommended first action presented (not a raw dump)
- [ ] If `sync_sweep_cmd` is set: the sweep ran; clean fast-forwards surfaced as a proposed action

## Notes
- Pairs with `/handoff`: handoff writes each lane's `### Next` → standup reads it. If a session ended without a journal entry, say so — the briefing will be weaker and should lean harder on tickets + git state.
- **Two bootstrap paths — don't conflate them.** `/standup` is the *heavy* cold-start bootstrap: a new day, a multi-hour break, or any time no fresh resume prompt is in hand. If you're resuming from a just-emitted `/lane-reset` prompt (an intra-day ticket boundary), that prompt **is** your bootstrap — paste it and keep working; do **not** run `/standup`. Running the heavy read at every ticket seam is exactly the all-day-session cost `/lane-reset` exists to avoid.
- Could later be promoted to a `SessionStart` hook for auto-bootstrap; kept operator-invoked for v1 to avoid per-session cost/noise.
